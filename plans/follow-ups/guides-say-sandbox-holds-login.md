# Two guides say every sandbox holds the login

- **Severity:** Medium. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-10, from round 4 of the review of pull request #170, branch `calummoore/billing-brainstorm`.
- **Location:** `src/marketing/docs/security.md:64` and `src/marketing/docs/agent-logins.md:123`.
- **Reason:** The model gateway change on `main` made the two passages stale, and the pricing page branch does not touch the guides or the gateway.

- **Source:** Review.
- **Category:** Docs or spec.
- **Terms:**
  - **Public guide:** a Markdown page of the marketing site under `src/marketing/docs/`. `docs/protocol/website-docs.md` gives the rules for its words.
  - **Model gateway:** the Worker routes that take the model requests of the agents in a cloud computer, add the agent login of the turn, and send them on to Anthropic or OpenAI.
  - **Version pin:** the lowest runner protocol version that a workspace accepts. A cloud computer with a version pin of 2 or later holds no agent login.
- **Background:**
  - `docs/protocol/model-gateway.md` says that a sandbox with a version pin of 2 or later holds no agent login. Its agents send each model request to the gateway with a turn token, and the gateway adds the login.
  - A runner of protocol version 1 still gets the agent login itself with each turn.
  - The Terms in `src/marketing/terms.ts` describe both cases: a newer cloud computer keeps the login outside, and an older one still receives it.
  - `src/marketing/docs/security.md:64` says: "The cloud computer receives the session's login when a turn needs it." The lines after it say that code with terminal access can read or copy that login.
  - `src/marketing/docs/agent-logins.md:123` says: "During a turn, its cloud computer uses the session starter's login." The lines after it say that code and members with terminal access can read or copy it.
  - `docs/protocol/website-docs.md:172` says that each public guide must agree with the Terms and Privacy pages.
- **Problem:** Both guides say that every cloud computer receives the agent login during a turn. Since the gateway change, only an older cloud computer does.
- **Impact if no action:** Readers get a wrong account of where their login lives, and the guides disagree with the Terms.
- **Root question:** How do the public guides describe where an agent login lives during a turn?
- **Options:**
  - **A.** Rewrite both passages to match the Terms and the gateway protocol. A newer cloud computer holds no login, and its agents reach the provider through the gateway. An older cloud computer still receives the login, and code with terminal access can read it until the org builds a new image. Effort: Small.
  - **B.** Change nothing until every org image is rebuilt. Effort: Small.
- **Left out:** Removing the passages, because the guides must still warn about older cloud computers. Two choices only exist, because the facts are settled in the protocol and the Terms.
- **Wider fix:** None. The repository rule already requires each change of a protocol fact to update every guide sentence that restates it.
- **Previous examples:** `plans/follow-ups/login-replacement-sharing-choice.md` records an earlier gap between a guide and the Terms.
- **Recommendation:** A. It makes the guides agree with the Terms, and it keeps the warning for older cloud computers.
- **Action:** fix after merge, apply A, because the gateway change caused the gap, and this branch does not change the guides.
