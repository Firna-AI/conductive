# Preview checks depend on the network's read size

- **Severity:** Medium. **Effort:** Small. **Confidence:** Low. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-11, from branch `calummoore/npm-run-dev-preview-issue`, the blocked wider fix of item 1.
- **Location:** `worker/previews/connection.ts:118`, and the test "uses HTTP backpressure to read one response chunk only when the browser requests it" in `worker/previews/flow.test.ts`.
- **Reason:** the wider fix changes the rule that preview streams read only when the browser asks for data, and nobody has measured whether production needs it.

- **Source:** Implementation. **Category:** Performance.
- **Terms:**
  - **Access check:** one D1 read of a preview and its viewer, `readPreviewAccess` in `worker/previews/viewer-access.ts`. Concurrent waiters of one viewer share one read.
  - **BYOB reader:** a stream reader that fills a buffer that the caller gives. It returns as soon as some data waits.
- **Background:**
  - The protocol requires a check of the preview and its viewer for each request and each batch of preview data, as "Previews and their viewers" in `docs/protocol/suspension-workspaces.md` says.
  - The preview proxy passes no body data to the browser before an access check that started after the data arrived. `worker/previews/README.md` adds that streams read only when the browser asks for data, one chunk at a time.
  - The default reader of a Workers fetch body gives 4 KB at most for each read. So each 4 KB waited for its own check, and a 3.9 MB file needed 942 checks one after another.
  - Branch `calummoore/npm-run-dev-preview-issue` reads byte streams with a BYOB reader. Its buffer starts at 16 KB and doubles after each full read, up to 256 KB.
  - The branch measured a load of the Conductive dev server, `npm run dev`, through a local workerd copy of the proxy. The copy waited 50 ms for each D1 read and 100 ms for each sandbox request. The load took 100.6 seconds before the change and 15.4 seconds after it. A read-ahead prototype took 14.8 seconds.
  - Local workerd reads from a plain TCP socket, so its reads filled the large buffers. In production, data reaches the Worker through Cloudflare's network. Nobody has measured the size of each read there.
- **Problem:** A BYOB read returns as soon as some data waits. If production hands data to the Worker in small pieces, such as 16 KB, each check again covers little data.
- **Impact if no action:** If production reads stay small, a dev server preview stays slow. With 16 KB reads, the 3.9 MB file alone needs about 240 checks, or 12 seconds at 50 ms for each check.
- **Root question:** How does one access check cover all data that arrived during the previous check, whatever piece size the network gives?
- **Options:**
  - **A.** Keep the BYOB reads, and measure first. After the deploy, open a preview of `npm run dev` of this repository, and note the load time in the browser's network panel. A load near 15 seconds shows large reads. A load over 40 seconds shows small reads. Effort: Small.
  - **B.** Read ahead while a check runs, up to 256 KB for each connection. Release all data that arrived before the check started, so every byte still waits for a check that started after it arrived. It changes the rule that streams read only when the browser asks for data, and the backpressure test above. Effort: Medium.
  - **C.** Push each revocation to the workspace object, and drop the check of each batch. A sign-out, a suspension, or a removal from the org then closes the viewer's preview connections. It changes the protocol rule that each batch of data gets a check. Each revocation source must notify every workspace object of that viewer. Effort: Large.
- **Left out:** A check for each request only, or a time window after each check, was left out. Both let a revoked viewer receive data that no check covers, and option C stops that viewer's streams with no body checks.
- **Wider fix:** B, because each batch then holds all data that arrived during a check, whatever the read size.
- **Previous examples:** The 4 KB default reads that branch `calummoore/npm-run-dev-preview-issue` replaced with BYOB reads.
- **Recommendation:** A. The BYOB reads may already give large batches in production, and B changes a recorded rule and a test. Option B protects the codebase best if the measurement shows small reads.
- **Action:** ask the user, because the wider fix changes the rule that preview streams read only when the browser asks for data, and it changes an existing test.
