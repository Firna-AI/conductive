# A failed read can hide the page of an unlisted HTML file

- **Severity:** Medium. **Likelihood:** Rare. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-18, from the review of branch `calummoore/preview-html-file-c42r`, finding 102.
- **Location:** `src/files/page/FilePage.tsx:87` and `:92`, `src/files/model/file-labels.ts` (`pageLabel`, `tabLabel`, `tabHidesSecret`), `worker/files/errors.ts`, `src/shared/files.ts`.
- **Reason:** A Rare product bug of Medium severity waits for a later branch under the fix rule.

- **Terms:**
  - **Label:** the text that a screen shows in place of a real path, with each secret value hidden. Only the Worker makes it. `src/files/labels.md` gives the rules.
  - **readLabels:** the labels that the files store keeps from each good read of a file.
  - **Files preview:** the preview on the preview domain that shows the page of an HTML file in its tab.
- **Background:**
  - The tab of an HTML file shows its page only when its label hides no secret value, because the address of the page holds the real path. A file with no known label counts as hiding one.
  - `FilePage` takes the label from the reply of its read, and else from the file lists, through `pageLabel`. `pageLabel` does not read `readLabels`, but `tabLabel` does.
  - All files lists only the ignored files of the context folder. An HTML file in another ignored folder, such as `coverage/`, is in no list. A typed address or a kept tab opens it.
  - The plan of the change recorded that in Preview only a read that finds no file replaces the page.
- **Problem:** When a later read of such an unlisted file fails, or the file grows past the read limit of 5 MiB, `pageLabel` gives no label. The tab then counts the label as hiding a secret value, and it shows the read error in place of the working page. At each return to the tab, the header also shows "File" with no switch until the new read answers. An unlisted HTML file over 5 MiB never shows its page, because no read gives its label.
- **Impact if no action:** A rare read failure replaces a working page of an unlisted file with an error, and a large unlisted page cannot show.
- **Root question:** How should the Preview of an HTML file that no list names get its safe label when its read fails or is over the read limit?
- **Options:**
  - **A.** Use the saved read label as a fallback in `FilePage`. Add a regression test without a list entry. Effort: Small.
  - **B.** Make `pageLabel` read "the reply label, else `tabLabel`", so the page and the tab share every source of a label. Use it for the header and for the Preview rule. Add the regression test. Effort: Small.
  - **C.** Read the label apart from the content of the file. This needs new API work. Effort: Medium.
  - **D.** Apply B, and add the safe label as `displayPath` to the error replies of the file read route, at least `file_too_large`, so that the store can save it. The field is additive: older clients ignore it. It changes `FileTooLargeResponse` and a protocol page. Effort: Medium.
- **Left out:** The raw path as the label, because it can show a secret value. No change, because it breaks the recorded rule that only a missing file replaces the page.
- **Wider fix:** D, because the Preview rule then needs no read that fits.
- **Previous examples:** Commit `c710a306c` fixed the same missing-label class for file tabs with `readLabels` and `tabLabel`.
- **Related:** The kept files preview after a return was fixed on the same branch. B gives an unlisted file its label at the first render of a return, so it needs that fix, which is already in place.
- **Recommendation:** B. It uses the existing label store with the smallest change.
- **Action:** fix after merge, apply B, because a Rare product bug of Medium severity waits for a later branch under the fix rule.
