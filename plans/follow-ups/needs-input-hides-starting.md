# A waiting request hides Starting from the app

- **Severity:** Medium. **Likelihood:** Common. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-18, from the review of branch `calummoore/preview-html-file-c42r`, finding 52.
- **Location:** `worker/lifecycle/workspace-state-projection.ts:51-55`, `worker/secrets/request-records.ts:140`, `src/shell/workspace/features.ts:157-170`, `src/shell/workspace/previews/use-html-preview.tsx:116-153`, `docs/protocol/secret-requests.md:111-113`, `docs/protocol/agent-tools.md:216-219`, `docs/protocol/restart-the-software.md:64-65`.
- **Reason:** The recommended fix changes the rule that a workspace keeps needs input while any request waits, and only the user can change that rule.

- **Terms:**
  - **Needs input:** the workspace state `input`, which shows while an agent request waits for a member, such as a request for secrets or a Mac command.
  - **Late request:** a secret request that stays open after its agent call ended, so that a member can still answer it. `docs/protocol/secret-late-answers.md` gives its rules.
  - **Files preview:** the preview on the preview domain that shows the page of an HTML file in its tab. `docs/protocol/html-file-preview.md` gives its rules.
  - **Restart:** the control in the workspace header that downloads the newest release and restarts the agent runner. The workspace shows Starting until the runner is ready again.
- **Background:**
  - The Worker projects the shown state of a workspace. While a request waits, it shows `input` in place of `starting` (`workspace-state-projection.ts:51-55`). The waiting count also counts late requests, which a Restart does not end.
  - The app maps `input` to a running cloud computer (`features.ts:157-170`). So while a request waits, the app sees no Starting during a Restart or a resume.
  - The HTML file preview opens the files preview again when the workspace leaves Starting, so that the "Restart to preview this file" notice clears after a Restart installs newer software (`docs/protocol/html-file-preview.md`).
  - `docs/protocol/restart-the-software.md:64-65` says that the header and the row show Starting until the runner is ready. The public guide says "The header shows **Starting** until the agents are back". `docs/protocol/secret-requests.md:111-113` says that the workspace keeps needs input while any request waits, also a late request. The two rules conflict while a request waits.
- **Problem:**
  - After a Restart while a request waits, the HTML tab never sees the end of Starting, so the older-software notice stays until the member shows the tab again.
  - At a resume while a late request waits, the tab opens the files preview before the runner connects, and it shows a false "Restart to preview this file" notice that no later event clears.
  - The same hidden Starting makes other parts act as if the cloud computer runs: the tools, the file reads, the port previews, the terminal, the Restart menu, and each Worker check that uses `sandboxAccessPredicate` (`worker/data/sandbox-access.ts:12`).
- **Impact if no action:** A member sees a stuck or false notice in an HTML tab, and must switch tabs to recover. Other members see Needs input for the whole Restart.
- **Root question:** How does the app learn that the cloud computer software is starting or ready again, also while a request waits for a member?
- **Options:**
  - **A.** Give Starting priority over needs input in the Worker's projection, and restore needs input after the runner is ready if requests still wait. Update `docs/protocol/secret-requests.md`, `docs/protocol/agent-tools.md`, `worker/lifecycle/recovery-and-shown-state.md`, and `worker/devices/README.md`, and check the legal pages and the public guides. Add a regression through the restart and the state publication with an unanswered secret request. Effort: Small.
  - **B.** Publish the running state apart from the requests that wait, and make the parts that need readiness read it. It changes the generated `Workspace` type and its consumers. Effort: Medium.
  - **C.** Publish an explicit event when the runner is ready, and renew the HTML tabs from it. Effort: Medium.
  - **D.** In the app alone, while the HTML tab shows the older-software notice, open the files preview again at a fixed interval, such as every 15 seconds, until the page shows or the tab hides. It fixes only the HTML tab, and the resume case still shows the false notice until the next try. Effort: Small.
- **Left out:** A refresh after the Restart reply, because it can come before the runner is ready and misses the Restart of another member. Ending the open requests at a Restart, because it breaks late answers. A narrower A that keeps needs input while the runner is connected, because A is better on every point.
- **Wider fix:** A, because it corrects the one writer of the shown state, so every part that reads readiness sees Starting again.
- **Previous examples:** Commit `93ae7fc22` keeps Starting when turns end during a Restart. Commit `8c49081e3` corrects another case where the shown state hid Starting.
- **Related:** `plans/follow-ups/html-tab-open-before-confirmed-state.md`: its fix builds on the signal that this item chooses.
- **Recommendation:** A. It makes the shown state meet the Restart rule and the guide, with a Small change to one writer.
- **Action:** ask the user, because A changes the rule that a workspace keeps needs input while any request waits, which `docs/protocol/secret-requests.md` and `docs/protocol/agent-tools.md` state, and no recorded user decision covers that change.
