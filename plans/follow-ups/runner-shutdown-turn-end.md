# Runner shutdown leaves the running turn active

- **Severity:** Medium. **Likelihood:** Rare. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-06, from PR #12, branch `conductor/boat-native-remote-workspaces-milestone-7r`, a new problem of the round 2 check of finding 5.
- **Location:** `AgentEngine.close` in `runner/src/engine.ts`, `Runner.close` in `runner/src/runner.ts:105`, and the signal handler in `runner/src/main.ts:36`.
- **Reason:** on 6 November 2026 the owner told the branch that built the runner to record this note without a fix.

- **Terms:**
  - **Runner:** the agent runner, the Node program in `runner/` that runs the agents in a cloud computer and reports to the workspace.
  - **Workspace:** the Durable Object of one workspace. It owns the sessions, the turns, and the waiting input, and it stores the runner events.
  - **Active turn:** the turn that the workspace treats as running in a session. The chat shows its running state and Stop.
- **Background:**
  - The runner runs as the systemd unit in `runner/service/conducting-runner.service`. A stop sends SIGTERM to the runner and its agent processes at the same time, because the unit sets `KillMode=control-group`.
  - systemd ends each remaining process after 15 seconds. `Restart=always` starts the runner again 2 seconds after it ends, for any reason.
  - On SIGTERM, `runner/src/main.ts` calls `Runner.close`. It stops the file watcher, calls `AgentEngine.close`, and closes the connection. The process then exits with code 0.
  - `AgentEngine.close` waits for its queue, then closes the agent process of each session. It emits no event.
  - The state file keeps the unconfirmed events and the conversation references, but no turns. So the next runner process does not know which turns ran.
  - The workspace ends a turn only on `turn.completed` or `turn.failed` from the runner. It refuses an agent event for a turn that is no longer active, and it closes the connection on a refused event.
  - Since 6 November 2026, the runner answers an interrupt for a turn that it does not run with `turn.completed` state `stopped`.
  - The chat protocol says that a turn that stops with no Stop request, such as when the cloud computer stops, shows "The agent stopped".
  - Each runner fix must give one end event for each turn, whichever process ends first after SIGTERM.
  - An interrupt for the same turn can cross that end event. A fix must then send no second end event, because the workspace refuses it.
- **Problem:** When the runner shuts down during a turn, no end event of that turn leaves the runner. After a resume, the workspace still treats the turn as active, and no agent runs it.
- **Impact if no action:** The chat shows the turn as running until a member presses Stop. A message sent to that turn gets no answer, and Stop then discards it, as Stop does with unread input.
- **Root question:** How does a turn end when the runner stops while the turn runs?
- **Options:**
  - **A.** End each active turn in `AgentEngine.close`, before `Runner.close` closes the connection. Emit `turn.completed` with state `stopped` and the changed files. The state file keeps the event until the workspace confirms it, so the next start sends it again. This covers each stop that sends SIGTERM. Effort: Small.
  - **B.** Save the IDs of the running turns in the state file, and end each saved turn as stopped at the next start. This covers a crash or a kill too. The end event waits for the next start, and the changed files are lost with the checkpoint in memory. Effort: Medium.
  - **C.** Let the workspace end each active turn as stopped when it learns that the sandbox stopped. This covers a stop that runs no runner code, but not a runner crash in a running sandbox. It changes the chat backend and the workspace lifecycle code. Effort: Medium.
  - **D.** A and B together. A gives a prompt end with its file list for a normal stop. B covers the stops and crashes that A misses. Effort: Medium.
- **Left out:** Change nothing, and let a member press Stop: it fails the protocol rule that such a turn shows "The agent stopped".
- **Wider fix:** D. It ends each turn that a runner process leaves behind, also after a crash.
- **Previous examples:** None found.
- **Related:** `plans/follow-ups/runner-file-and-save-errors.md`, the same symptom from another cause: a turn that stays active in the workspace.
- **Recommendation:** D. It meets the protocol rule for each way that the runner stops, with no change outside the runner.
- **Action:** fix after merge, apply D, because on 6 November 2026 the owner told the branch that built the runner to record this note without a fix.
