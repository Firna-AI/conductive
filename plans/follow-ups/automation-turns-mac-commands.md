# An automation run can ask for commands on a Mac

- **Severity:** High. **Effort:** Medium. **Confidence:** High. **Harder later:** Yes.
- **Kind:** Needs decision.
- **Added:** 2026-11-09, from branch `calummoore/routines-feature-brainstorm`, decision 514 of its plan. Finding 2 of its review of 2026-11-10 found the same problem again. Updated 2026-11-21 on branch `calummoore/mac-permission-issue-o7fv`, after the user chose that agents can always ask.
- **Location:** `worker/automations/run-starter.ts:119` (the owner sends the first message of a run), `worker/tools/create.ts:109` (the calling turn's sender sends the first message of a created workspace), and the Mac command route in `worker/tools/mac-command.ts`. The rules are in `docs/protocol/agent-tools.md` ("Mac commands"), `docs/protocol/session-calls.md` ("The sender"), `docs/protocol/mac-access.md` ("Agents can always ask" and "Risks"), and `docs/protocol/automation-runs.md`.
- **Reason:** Each option adds a refusal or a new rule to the Mac command contract, and the user has not chosen one.

- **Terms:**
  - **Automation:** a saved prompt that starts an agent run in a new workspace, on a schedule, on a GitHub pull request event, or with Run now. The owner of the automation sends the first message of each run, so the run acts with the owner's logins.
  - **Mac command request:** an agent asks to run a command on the Mac of the person who sent its turn. The Mac app asks that person first.
  - **Always allow:** a choice that a person saves in the Mac app. A later request with the same command text then runs without a question.
  - **Mac access:** the switch of the Capabilities control in the Mac app. It is personal: on starts a grant until Stop of that workspace on the Mac of the member who turns it on, and off stops it. It does not decide whether agents can ask. A browser shows no switch.
  - **Grant until Stop:** the Mac app choice "Allow all commands until I stop". While it runs, every request from one workspace runs on one Mac without a question. Stop, also from the Mac access switch on that Mac, a quit of the Mac app, or a sign-out ends it.
- **Background:**
  - On 8 November 2026 the user chose option A of the decision "what one automation run works in": each run creates a new workspace, and the owner sends its first message.
  - A Mac command request goes to the Mac of the sender of the turn (decision 62 of the project). The Worker accepts a request only while that turn runs in the calling workspace.
  - The agent of a pull request run reads text that other GitHub accounts write: the code, the title, and the description of the pull request.
  - A workspace that a run's agent creates with the agent tools also sends its first turn as the owner (`worker/tools/create.ts:34`).
  - The session calls `create_session` and `send_message` of the agent tools also send each message as the sender of the calling turn, as "The sender" in `docs/protocol/session-calls.md` says. So a run's agent can start turns as the owner in each session of the org that is not archived, and those turns reach the owner's Mac too.
  - The first turn of a run carries no record that a trigger, not a person, started it. So the Mac route treats its requests as requests from a person's turn.
  - On 17 November 2026 the user chose that Mac access is off in each new workspace, also in a run workspace and in a workspace that an agent creates. While Mac access was off, the Worker refused each Mac command request of the workspace. So the first turn of a run reached no Mac.
  - On 21 November 2026 the user chose that agents can always ask for a command on a Mac, because the member can easily deny a request. The Worker no longer refuses a request while the stored Mac access of a workspace is off. The stored value stays off in each new workspace, but it gates no request. So the first turn of a run, and the first turn of a workspace that a run's agent creates, can ask for a command on the owner's Mac.
  - On the same day the user chose one personal Mac access switch in the Capabilities control of the Mac app. On starts a grant until Stop of that workspace on the Mac of the member who turns it on, and off stops it. A browser never starts a grant. `docs/protocol/mac-access.md` gives these rules. So the owner's Mac often holds a grant until Stop for a workspace where the owner turned the switch on.
  - The grant of the switch is personal. A run's turns have the owner as their sender, so they reach only the owner's Mac, never the Mac of another member.
- **Problem:** Text in a pull request, or in any page that a run reads, can make the agent of a run ask for a command on the owner's Mac. Mac access no longer gates requests, so the agent can ask from the first turn of the run. When the owner chose Always allow for that command, it runs without a question, in a folder that the request names. Each other command asks the owner, who may not watch the run. The owner's Mac can also hold a grant until Stop for another workspace, from the Mac access switch in the Mac app. The run's agent can then use `send_message` or `create_session` into that workspace. The new turn has the owner as its sender, so its requests go to the owner's Mac, and the grant runs any command there without a question.
- **Impact if no action:** A GitHub account outside the org, or text that a scheduled run reads, can run an always-allowed command on the owner's Mac from the first turn of any run, while nobody watches. Through a workspace where the owner's Mac holds a grant until Stop, it can run any command there. Each owner who turns the Mac access switch on in the Mac app adds such a workspace.
- **Root question:** When no person sent a turn, how does a member's Mac run only the commands that the member allowed for such a turn?
- **Options:**
  - **A.** Record it as an open risk in `docs/protocol/automations.md`, and change nothing else. Effort: Small.
  - **B.** The first turn of a run gets a refusal that says that runs cannot use a Mac. Later messages that members send in the run workspace keep the normal rule. A session that the run's agent sends a message to still reaches the owner's Mac. So does the first turn of a workspace that the run's agent creates. Effort: Medium.
  - **C.** Each request from the first turn of a run asks, also for an always-allowed command. An older Mac app ignores the new field and still runs an always-allowed command, and a waiting request has no time limit of its own. Effort: Medium.
  - **D.** Each message records whether a person started it. A message that a member sends counts. The first message of a workspace that the agent tools create, and each message of the session calls, copies the record of the calling turn. The Mac route serves a turn only when a person started its first message, and refuses every other turn with its reason. It needs a field on stored messages and a change to the create and send paths of the agent tools. Effort: Medium.
  - **E.** The Mac route refuses each request from a run workspace, and from each workspace that its agent created, whoever sends the turn. No member can use a Mac there. A turn that its agent starts in another workspace with the session calls still reaches the owner's Mac. Effort: Medium.
  - **F.** Always allow covers the command text in one workspace only. A run workspace then has no saved command, so each request asks. It changes the Mac app, This Mac, a mockup, and protocol text, and an older Mac app keeps the old scope. A turn that the run's agent starts with the session calls in a workspace where the owner's Mac holds a grant until Stop still runs each command without a question. Effort: Medium.
  - **G.** D, and the automation page gets a switch, "Runs can ask for commands on my Mac", off by default. Effort: Large.
- **Left out:** A refusal of the create call and the session calls of the agent tools in a turn that no person started, because D closes the same paths and keeps the calls. A rule for pull request runs only, because a scheduled run can read pull requests too, and no person watches it. An instruction in the run text not to use a Mac, because pull request text can override it.
- **Wider fix:** D. It gives a Mac only to a turn that a person started, so a later path without a person gets no Mac.
- **Previous examples:** None found.
- **Recommendation:** D. It refuses what B refuses at about the same cost, and it also closes the paths through a workspace that the run's agent creates and through a message of the session calls.
- **Action:** ask the user, because D adds a refusal to the Mac command route, and the user keeps each new refusal for themselves.
