# Guide asks for a build the app starts

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-10, from branch `calummoore/bootstrap-v139`, a read of the public guides for the change that links New workspace to the Cloud computer tab while the first build runs.
- **Location:** `src/marketing/docs/get-started.md:218` and `src/marketing/docs/cloud-computer.md:60`.
- **Reason:** The steps were imprecise before that branch, and the branch changes no guide sentence, so one docs branch fixes both guides.

- **Terms:**
  - **First build:** the build that makes the first org image of a new org. Create org starts it by itself.
  - **Added build:** one more build that the app starts by itself when the repositories or the install script changed during the first good build.
  - **Build computer:** the button on the Cloud computer tab of the org settings that starts a build. After a failed build, Try again takes its place.
- **Background:**
  - The public guides in `src/marketing/docs/` tell users how to change the install script of the cloud computer.
  - `get-started.md` gives five steps. Step 5 says "Select **Build computer** after any current build finishes."
  - `cloud-computer.md` gives the same steps. Its step 4 says "Select **Build computer**." Its lines 133 to 135 say that changes during the first successful build get one extra build automatically.
  - The section "The first build" of `docs/protocol/org-image.md` says that a change of the install script during the first good build gets the added build. The Cloud computer tab then asks for no build.
  - `HeadAction` in `src/shell/settings/BuildCard.tsx` shows Try again after a failed build, and Build computer otherwise.
  - Since that branch, the notice over the New workspace composer links an admin to the Cloud computer tab while the first build runs. So more admins can save a script during that build.
- **Problem:** For a script saved during the first build, step 5 of `get-started.md` asks for a build that the app starts by itself. After a failed build, the step names Build computer, but the tab shows Try again.
- **Impact if no action:** An admin who follows the steps runs one build more than needed, which costs a start of a cloud computer and time. After a failed build, the admin looks for a button that the tab does not show.
- **Root question:** How do the guide steps for a changed install script match what the app does during and after the first build?
- **Options:**
  - **A.** Change nothing. During the first build the tab itself says that one more build runs the script, and it asks for no build. Effort: Small.
  - **B.** After the steps in each guide, add one sentence that points to the first-build rule of `cloud-computer.md`. Effort: Small.
  - **C.** Reword the build step in both guides: select Build computer, but skip it during the first build, because the app builds the saved script when that build succeeds, and select Try again after a failed build. Effort: Small.
- **Left out:** A change of the app that refuses a build after an added build, because the problem is the words of the guides, not the app.
- **Wider fix:** None. The rule that a guide follows the protocol docs is already in force, in `docs/protocol/website-docs.md` and the repository rules.
- **Previous examples:** Commit `1e6e28b7` updated the guide "Sessions and chat", which restated a removed label.
- **Recommendation:** C. Each step is then true in each state of the first build, with one or two sentences.
- **Action:** fix after merge, apply C, because the problem is outside the scope of that branch.
