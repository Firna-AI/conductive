# Read-only Mac app copies never update

- **Severity:** Medium. **Likelihood:** Common. **Effort:** Small. **Confidence:** Medium. **Harder later:** Yes.
- **Kind:** Fix after merge.
- **Added:** 2026-11-09, from decision 4 of the Mac app update plan on branch `calummoore/desktop-app-auto-update`. The user chose no change for that branch, and option D as a follow-up.
- **Location:** The updater start in `desktop/src/main.ts`, `desktop/src/updates.ts`, and the section "Packages and updates" of `docs/protocol/desktop-app.md`.
- **Reason:** the user chose on 9 November 2026 to ship self-updates first and to add the move offer after them.

- **Terms:**
  - **Squirrel.Mac:** the macOS update framework inside Electron. It replaces the app bundle when an update installs.
  - **Read-only volume:** a disk that the app cannot write to, such as a mounted DMG.
  - **App Translocation:** macOS runs a downloaded app from a hidden read-only copy until the user moves it with Finder.
- **Background:**
  - The Mac app updates itself from the GitHub releases of `Firna-AI/remote-code`. It checks at launch and every 4 hours, and it downloads a new version in the background.
  - The app shows "The update is ready." with Restart now and Later only after Squirrel.Mac accepts the update.
  - People install the app from a DMG. Its window shows the app next to an Applications folder to drag it to.
  - Some people open the app straight from that window. The app then runs from the mounted DMG, which is read-only. An app opened from Downloads without a move can also run read-only, through App Translocation.
  - Squirrel.Mac can replace the app only where it can write. A copy in Applications, or in another writable folder, updates. A read-only copy downloads each update, about 130 MB, and Squirrel.Mac refuses to install it.
  - The protocol says that a failed update shows no error. So a read-only copy shows nothing, and only the log records the refusal.
  - Electron 44 has `app.isInApplicationsFolder()` and `app.moveToApplicationsFolder()` for macOS. The move puts the app in Applications and restarts it.
  - Mokly's desktop app offers "Open release page" for Linux packages that cannot update themselves.
- **Problem:** A read-only copy downloads updates but never installs them, and the person does not learn why.
- **Impact if no action:** Some people stay on old versions without knowing it, also after a security fix. Each such copy also cannot receive this fix by an update, so it needs a manual install.
- **Root question:** How does a copy that cannot replace itself still reach the new version?
- **Options:**
  - **A.** Change nothing more. People who run the app from the DMG stay on their version. Effort: Small.
  - **B.** At launch, a release build outside an Applications folder shows "Move Conductive to Applications to get updates." with "Move to Applications" and "Not now". The move restarts the app. "Not now" hides the dialog until the next version. A copy in another writable folder also sees it, although it can update. Effort: Small.
  - **D.** The same dialog as B, but only when the app cannot write to its own location. The app tests this at launch, and the test fails with the read-only volume error. A copy in another writable folder sees nothing. Effort: Small.
  - **E.** The same dialog, but only when Squirrel.Mac refuses a downloaded update and the app is on a read-only volume. People who never get an update never see it. The dialog comes only after a download. Effort: Small.
- **Left out:**
  - An offer after a failed update that reads the error text of Squirrel.Mac: E checks the location itself, so E is better on every point.
  - An installer package instead of the DMG: it installs an app that root owns, so each later update needs an administrator password. It fails the goal.
  - An "Open release page" link: it leaves the copy where it cannot update, so each version needs a manual install. D and E fix the cause with the same single dialog.
- **Wider fix:** None. The app already waits for Squirrel.Mac before it offers Restart now, which covers every refusal. The options differ only in when they offer the move.
- **Previous examples:** Mokly's "Open release page" offer for Linux packages that cannot update.
- **Recommendation:** D. It asks once, at launch, and only when the copy cannot update. E best avoids a dialog for people who never get an update.
- **Action:** fix after merge, apply D, because the user chose D as a follow-up on 9 November 2026, after the first release with self-updates.
