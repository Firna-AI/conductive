# Developer tools send usage data to their makers

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-08, from the branch `calummoore/astro-marketing-site-switch`, which moved the marketing site to Astro. The implementor raised it, and an options check widened it the same day.
- **Location:** `package.json`: the scripts `dev`, `build`, `site:dev`, and `site:build` run Astro, and the scripts `types` and `db:migrate` run Wrangler. `worker/marketing/built-site.test.ts` runs `astro build`. `docs/deployment.md` gives `npx wrangler` commands. `wrangler.jsonc` and `astro.config.ts` are the config files of the two tools.
- **Reason:** Nothing depends on the answer, and no rule or requirement says what developer tools may send, so the choice waits for the user.

- **Terms:**
  - **Telemetry:** anonymous usage events that a tool sends to its maker. Astro stops only when `ASTRO_TELEMETRY_DISABLED` or `TELEMETRY_DISABLED` is set, or when a person runs `astro telemetry disable` on their machine. Wrangler stops with `DO_NOT_TRACK`, `WRANGLER_SEND_METRICS=false`, or `"send_metrics": false` in `wrangler.jsonc`.
- **Background:**
  - Astro 7 builds the marketing site. `astro build` and `astro dev` send one event on each run, also in CI. CI detection only skips Astro's first-use notice. `astro check` sends only when it crashes.
  - Each Astro event holds an anonymous machine ID, a hashed project ID, system facts, the name of the site's build integration, and the AI agent that runs the tool.
  - Wrangler sends the same kind of event from each command, also in CI. Every Wrangler command reads `send_metrics` from `wrangler.jsonc`, also the deployment commands of `docs/deployment.md`.
  - `npm run test` runs `worker/marketing/built-site.test.ts`, which starts `astro build` with an environment that holds only `PATH` and `CI`. So a variable from a script or from CI does not reach it.
  - A read of the installed packages on 8 November 2026 found no other tool that sends usage data from the npm scripts. The Cloudflare Vite plugin already turns off the telemetry of Miniflare. Vite, Vitest, Prettier, ESLint, TypeScript, Mokly, sharp, Electron, Playwright, and esbuild send none.
  - The picture capture command, `npm run marketing:pictures`, starts the system Chrome without `--disable-background-networking` (`tools/marketing-pictures/cdp.ts`). Nobody checked what Chrome sends.
  - The agents that the runner starts in user sandboxes are product code, not developer tools. The runner already sets `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, and Codex analytics are off by default.
- **Problem:** Each developer machine, agent sandbox, and CI run sends Astro and Wrangler usage events. No recorded rule says what developer tools may send.
- **Impact if no action:** The events continue. They hold no code or secrets, but they show tool use, timing, and the agent in use to two third parties.
- **Root question:** Should the developer tools that this repository runs send usage data to their makers, from each place that runs them?
- **Options:**
  - **A.** Change nothing. Effort: Small.
  - **B.** Turn off Astro telemetry in the scripts that run Astro, and in the built-site test. Effort: Small.
  - **C.** Turn off the telemetry of Astro and Wrangler in the scripts and the built-site test, and state the rule under "Repository rules" in `AGENTS.md`. Direct `npx wrangler` commands still send. Effort: Small.
  - **D.** Turn off Wrangler with `"send_metrics": false` in `wrangler.jsonc`, which reaches every Wrangler command. Turn off Astro with `ASTRO_TELEMETRY_DISABLED=1` in `site:build`, `site:dev`, and the environment of the built-site test. Add the rule to `AGENTS.md`: use a tool's own config switch first, and the scripts only when the tool has none. A new place that runs Astro still sends until it sets the variable. Effort: Small.
  - **E.** Turn off both tools only in CI, with an `env` block in `.github/workflows/ci.yml`, and leave each machine to its person. Developer machines and agent sandboxes still send. Effort: Small.
  - **F.** Put both switches in the config files: `"send_metrics": false` in `wrangler.jsonc`, and `ASTRO_TELEMETRY_DISABLED` set at the top of `astro.config.ts`. Then no script, direct command, test, or API call sends. The Astro line relies on an order inside Astro that Astro does not document, so a later release can break it without a sign. Effort: Small.
- **Left out:** `astro telemetry disable` on each machine alone, because it does not reach CI. `DO_NOT_TRACK` for both tools, because Astro ignores it. A gate check of each place, because it would test run strings and the behaviour of third-party tools. A block at the network, because it needs infrastructure. Other tools, because the site builds with Astro and the Worker deploys with Wrangler.
- **Wider fix:** F, because it reaches each place that loads the two config files. It relies on undocumented behaviour of Astro.
- **Previous examples:** Wrangler telemetry, which was on by default before the move to Astro.
- **Recommendation:** D. It uses only the switches that the tools document, and Wrangler's config key also reaches the deployment commands. F protects best against a new place that runs Astro.
- **Action:** ask the user, because the choice sends or keeps data with third parties, and no requirement or recorded decision covers what developer tools may send.
