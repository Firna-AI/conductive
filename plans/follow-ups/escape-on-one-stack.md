# Put every Escape handler on one stack

- **Severity:** Medium. **Likelihood:** Rare. **Effort:** Medium. **Confidence:** Medium. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-16, from branch `calummoore/milan-hmhx`, the wider fix of review item 1. Updated 2026-11-20, from branch `calummoore/italic-tab-close-with-esc-s97a`, the wider fix of review item 3. Updated 2026-11-23, from branch `calummoore/popup-closes-on-click-outside-4lj3`, a problem outside the review scope.
- **Location:** `src/shell/ui/escape-layer.ts`, `useEscapeLayer` and its check for an open native dialog. `src/members/ui/modal.ts`, `useModalDialog`. `src/app/pointer-drag.ts`, the Escape listener on `window`. `src/app/long-press.ts`, the Escape listener on `window`. `src/chat/ui/dismiss.ts`, `useEscape`. `src/shell/shortcuts/page-escape.ts`, `usePageEscape`. `src/shell/list/WorkspaceNameField.tsx`. `src/shell/list/SectionHeader.tsx`, `RenameField`. `src/shell/palette/PalettePanel.tsx`, `onKeyDown`. `src/shell/layout/ListPopover.tsx`, `useDismiss`. `src/chat/explain/ExplainPopover.tsx`, `onKeyDown`. `src/chat/device/CommandChoices.tsx`.
- **Reason:** The wider fix changes the Escape handling of the palette, the rename fields, and the shared layer helper, outside the files of the branch.

- **Terms:**
  - **Escape stack:** the open layers of `useEscapeLayer` in `src/shell/ui/escape-layer.ts`. The newest layer takes each Escape in the capture phase and stops it.
  - **List popover:** the whole sidebar of the current org, open over the page beside the org rail while the sidebar is hidden, from `src/shell/layout/ListPopover.tsx`.
- **Background:**
  - Menus and dialogs close on Escape through the Escape stack. The rename fields and the palette handle Escape in their own key handlers, which run after the capture phase.
  - The list popover first used the Escape stack too. Then it took Escape before a rename field inside it, and the field saved the typed name on blur. The branch fixed this directly: the popover now listens for Escape after the page, and leaves a key that a handler took, a key that an input method composes, and a key in its own text field.
  - So two Escape mechanisms stay. Each new layer must choose one, and a layer on the stack can still take a key that a newer field owns.
  - The pointer drag of `src/app/pointer-drag.ts` is a third mechanism. During a drag of a row or a section, it listens for Escape on `window`. Since 2026-11-20 it calls `preventDefault` on that Escape. A key still reaches `document` before `window`, so Escape during a drag in the list popover ends the drag and also closes the popover. In the visible sidebar, the same Escape ends only the drag. Review item 11 of 2026-11-16 confirmed it with a test.
  - Since 2026-11-20, Escape also closes the shown temporary tab, the file tab with an italic title, as `docs/protocol/temporary-tabs.md` says under "Close the tab". `usePageEscape` of `src/shell/shortcuts/page-escape.ts` runs that action at the end of the bubble phase of `window`. It acts only when no menu, dialog, or sheet was open in `OpenLayers` of `src/shell/ui/layers.ts` as the press started, and when no handler called `preventDefault` or stopped the press. So each part that takes Escape without a layer must mark the key by hand: the pointer drag, the long press of `src/app/long-press.ts`, and the list popover now call `preventDefault` for this. Each has a test of `defaultPrevented`: `src/chat/components/TabDrag.dom.test.tsx`, `src/files/panel/RowMenu.mounted.test.tsx`, and `src/shell/layout/ListPopover.test.tsx`.
  - `useEscape` of `src/chat/ui/dismiss.ts` takes Escape on `document` with no `preventDefault`. Its users today also note a layer in `OpenLayers`, so the temporary tab stays. A new user that notes no layer would let the same press also close the temporary tab.
  - The Explain popover of `src/chat/explain/ExplainPopover.tsx` closes on an Escape that reaches its own `onKeyDown`. The menu **More ways to allow** of `src/chat/device/CommandChoices.tsx`, in a request card inside the popover, closes on Escape through `useEscape` with no `preventDefault`. So one Escape in that menu closes the menu and the popover, and the focus goes back to the mark.
  - `useEscapeLayer` also takes Escape while an input method composes, so an open dialog or menu closes on a key that the input method needs, against `docs/protocol/keyboard-shortcuts.md`.
  - Settings, from branch `calummoore/sync-user-and-org-settings-r8nj` of 2026-11-20, is a dialog on the Escape stack whose tabs hold parts of the members kit and hand-written Escape handlers. Escape in the shortcut recorder and in the role menu of Members closed all of Settings. That branch put the edit row of Keyboard shortcuts and the desktop menu of the members `ChoiceMenu` on the stack, and made the stack leave Escape alone while a native `<dialog>` of the members kit is mounted, with `document.querySelector('dialog')`, also in the moment while a busy question opens again. The native dialogs of the members kit and the menus of the chat kit still do not join the stack, so each new one in a layer needs the same care.
- **Problem:** Escape has several mechanisms, and an older layer can take a key that a newer field, palette, or drag owns. Each part that takes Escape outside the stack must also remember to call `preventDefault`, or the temporary tab closes too.
- **Impact if no action:** A later layer on the stack, opened over a rename field or under the palette, can drop a rename or need two presses of Escape.
- **Root question:** How does Escape always reach the newest field or layer that the person opened?
- **Options:**
  - **A.** Keep the two mechanisms, and add a comment in `Overlay.tsx` that says when a layer must not use the stack. Effort: Small.
  - **B.** Put every Escape handler on the Escape stack, in `src/shell/ui/layers.ts` beside `OpenLayers`, which already notes the menus and dialogs of the shell, chat, and members kits. The members `useModalDialog` joins as a layer that leaves Escape to the browser, so the `dialog` query of `useEscapeLayer` goes. The palette closes through `useEscapeLayer`, each rename field adds a layer that cancels it, the pointer drag and the long press add a layer while a press is held, `useEscape` of `src/chat/ui/dismiss.ts` moves to the stack, and the list popover moves back to the stack. `usePageEscape` then becomes the bottom of the stack: it runs only when no layer took the key, and the `preventDefault` calls that mark a taken key go. `useEscapeLayer` leaves a key during text composition to the text. Keep the tests of `src/shell/layout/ListPopoverLayers.test.tsx` and `ListPopoverGuards.test.tsx` green, and add a test that Escape during a drag in the popover ends only the drag. Effort: Medium.
- **Left out:** A marker that the stack honours on the elements that own their Escape. It keeps two mechanisms, so B is better on every point.
- **Wider fix:** B. One stack for every layer prevents the class.
- **Recommendation:** B. One stack gives each Escape to the newest field or layer, and it fixes the text composition gap of dialogs and menus.
- **Action:** fix after merge, apply B, because it changes shared code of the palette, the rename fields, and the layers, outside the files of the branch.
