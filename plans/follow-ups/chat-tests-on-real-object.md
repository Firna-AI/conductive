# The chat tests skip the real workspace object

- **Severity:** Medium. **Effort:** Large. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-08, the wider fix of finding 3 of PR #48 (Milestone 7v, option C of its check), with finding 1 of PR #49 (Milestone 8n), which its check moved outside the scope, and option C of finding 7 of PR #46 (Milestone 7w). Widened on 2026-11-08 by finding 19 of PR #53, branch `conductor/boat-native-remote-workspaces-milestone-8m`, round 1, to option D of its check.
- **Location:** `createChatFixture` and `MemoryChatStorage` in `worker/chat/harness.test-support.ts` and `worker/chat/memory-storage.test-support.ts`, which 37 chat test files use. `createRunnerLimitsFixture` in `worker/chat/runner-limits.test-support.ts`, which seven test files and `worker/chat/history-order.test-support.ts` use. The direct users of `MemoryChatStorage`: `worker/chat/history-pages.test.ts`, `worker/chat/history-snapshot.test.ts`, `worker/devices/recovery.test.ts`, `worker/chat/commit-boundary.test-support.ts:6`, and `worker/chat/history-order.test-support.ts:181-182`.
- **Reason:** the fix reaches the shared chat fixture and many test files outside the diffs that found it.

- **Terms:**
  - **Workspace object:** the Durable Object that owns one workspace's chat in production, with native SQLite storage.
  - **MemoryChatStorage:** the hand-written store that the chat test fixture uses. Its restart helper builds a new chat over the same map.
  - **createRunnerLimitsFixture:** a second chat fixture over `MemoryChatStorage`. It runs one `RunnerChannel` for the refusal, cap, file part, history order, and compaction tests.
- **Background:**
  - Most chat tests run on `MemoryChatStorage` with a simulated restart. A few native tests run the real object in Miniflare with a real eviction. `plans/follow-ups/lifecycle-tests-on-real-object.md` records the same class for the lifecycle tests.
  - Milestone 8m added shared checks for rejected commits, completed commits, and the compaction indexes of the history. `checkCommitBoundaries` in `worker/chat/commit-boundary.test-support.ts` requires `MemoryChatStorage`.
  - The faults of that store act on a copied `Map`, at `worker/chat/memory-storage.test-support.ts:46-58`, and its restart builds the chat again over that `Map`.
  - The compaction check runs on `createRunnerLimitsFixture`, at `worker/chat/history-compaction-commit.test.ts:12`. Two history tests build `MemoryChatStorage` directly.
- **Problem:**
  - A test that claims persistence, replay, or a restart can pass on the hand-written store while the real storage or the rebuild of the object loses the data.
  - No native test fails or interrupts a chat receipt commit on the production `Workspace`. The native tests in `worker/chat/adapter.test.ts` and `worker/chat/integration/` check only successful commits and restarts.
  - The compacted history read calls `list` with `end`, `reverse`, and `limit`, at `worker/chat/history-compaction.ts:79-84`. Milestone 8m added these options to the in-memory store too.
  - No test in the gate reads a compacted answer through native storage. The only native case with `assistant.completed`, at `worker/chat/integration/chat-read-state.test.ts:83`, sends no delta for that message before it.
- **Impact if no action:** A chat defect that only native storage shows can pass the gate, for example a lost queue, a lost mark, or a split commit.
- **Root question:** How do the chat tests prove persistence through the real object and its storage?
- **Options:**
  - **B.** Extract one shared native event fixture from the existing durable chat tests, and move each test that claims persistence or a restart onto it. Effort: Medium.
  - **C.** Make the shared chat fixture run the production object in Miniflare by default, with real eviction for each restart, and keep its fault controls and every assertion. Effort: Large.
  - **D.** Remove the in-memory store. Effort: Large.
    - Do C. Also move `createRunnerLimitsFixture`, and each test that builds `MemoryChatStorage` directly, onto native storage. Then delete `MemoryChatStorage` and its fault flags `beforeCommit` and `crashAfterCommit`.
    - A native fixture can still inject both commit faults. `worker/github/sqlite-worker.test-support.ts:37-40` already wraps `ctx.storage.transaction`, and it throws inside the native transaction at line 94. A throw after the native transaction returns models a crash after the commit.
    - A test entry can wrap the object context before the production constructor runs, as `worker/chat/integration/workspace-recovery-entry.test-support.ts:15-26` does. So the product code needs no change.
    - Update `worker/chat/tests.md`, which describes both fixtures and the fault flags.
    - After that, no later test can use a hand-written chat store.
    - Cost: more native cases in the gate. So D depends on the speed work of `plans/follow-ups/harness-test-speed.md`, which Milestone 5f also holds.
    - D matches option E of `plans/follow-ups/lifecycle-tests-on-real-object.md`, which removes the in-memory store of the lifecycle.
- **Left out:**
  - Another hand-written store, because it keeps the same weakness.
  - One native case for the shared commit path, `this.storage.transaction` in `ChatStore.change` at `worker/chat/store.ts:223`, with the other receipt cases on the in-memory store. It keeps the hand-written store, so later tests can still skip native storage, and it fails the goal. It is the smaller step only if a native proof must come before Milestone 5f.
  - More successful native round trips. `worker/chat/adapter.test.ts` and the `worker/chat/integration/` tests already make them, and they reach neither commit boundary, so they fail the goal.
  - A Node stub that builds the production `Workspace` over the in-memory store. It keeps the hand-written store, as `plans/follow-ups/lifecycle-tests-on-real-object.md` says.
  - Each case on both stores. The testing rules run a test on a second runtime only when the requirement differs there, and D gives the native proof with fewer cases.
  - A parity test of the in-memory store against native storage. The testing rules give no test to the internals of a test harness. A one-time proof also misses later drift and the rebuild of the object.
- **Wider fix:** D. No later test can use a hand-written chat store. C prevents the class only in the default fixture.
