# A new terminal does not take the focus

- **Severity:** Medium. **Likelihood:** Common. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-16, from the branch `calummoore/terminal-tabs-implementation-l5ml`, Milestone 7 of the terminal tabs change.
- **Location:** `src/shell/workspace/tools/TerminalPart.tsx:39`, `src/terminal/useTerminalActions.ts`, `src/shell/workspace/WorkspacePaletteActions.tsx`.
- **Reason:** Each option that moves the focus for these controls adds behaviour that no requirement states.

- **Source:** Implementation.
- **Category:** Product bug.
- **Terms:**
  - **Command palette:** the list of actions that ⌘K on a Mac, or Ctrl+K on Windows and Linux, opens. `docs/protocol/command-palette-actions.md` lists the actions of an open workspace.
  - **Terminal tool:** the tool of a workspace that shows its terminals, in the right column on desktop. Its tab row has a + that opens a new terminal. `docs/protocol/terminal.md` gives the rules.
- **Background:**
  - On desktop, a click on the Terminal tab of the tools panel and Go to Terminal move the focus to the shown terminal, as "The shell" in `docs/protocol/terminal.md` says. The user chose this on 16 November 2026.
  - The palette row New terminal opens a terminal and shows the Terminal tool. The + of the terminal tabs opens a terminal and shows it. A click on a terminal tab shows its terminal.
  - None of these three controls moves the focus to the terminal. When the palette closes, the focus goes back to where it was before the palette opened. This is often the message box of the chat. No requirement says where the focus goes after these controls.
  - On Windows and Linux, a terminal with the focus keeps every key, also Ctrl+K. `plans/follow-ups/terminal-keyboard-trap.md` holds that older problem.
- **Problem:** A user who runs New terminal from the palette and then types, types into the message box. Enter then sends that text to the agent as a chat message. After the + or a terminal tab, the focus stays on the tab row.
- **Impact if no action:** Users send commands to the agent by mistake, and they must click the terminal before each use.
- **Root question:** Where does the keyboard focus go when a control shows a terminal?
- **Options:**
  - **A.** Keep the focus where it was. Effort: Small.
  - **B.** Give the focus to the new terminal after New terminal from the palette, on desktop. On Windows and Linux, the user then cannot reach Ctrl+K until a click outside the terminal. Effort: Small.
  - **C.** Do B, and give the focus to the new terminal after a press on the + of the terminal tabs. Effort: Small.
  - **D.** Do C, and give the focus to the terminal after a click on a terminal tab. A keyboard user who moves along the tabs with the arrow keys or Tab keeps the focus on the row. Effort: Medium.
- **Left out:** A notice that tells the user to click the terminal. It adds a step and does not stop the wrong message.
- **Wider fix:** D. One rule then covers each control that shows a terminal, as the rule for Go to Terminal does.
- **Previous examples:** The Terminal tab of the tools panel and Go to Terminal, which take the focus since 16 November 2026.
- **Recommendation:** D. It follows the rule that the user chose for the Terminal tab and Go to Terminal, and a user who shows or opens a terminal types in it next.
- **Action:** ask the user, because each option that moves the focus adds behaviour that no requirement states.
