# Daily refreshes spend starts on idle orgs

- **Severity:** Medium. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-10, from the options check of the pricing decisions of `plans/pricing-page.md`, branch `calummoore/billing-brainstorm`.
- **Location:** `docs/protocol/org-image.md:46` and `readImageSchedule` in `worker/lifecycle/image-schedule.ts:43`.
- **Reason:** The fix changes the refresh rule of the org image protocol, which only the user can change, and the pricing change does not touch the image.

- **Source:** Review.
- **Category:** Performance.
- **Terms:**
  - **Start:** each create or resume of a cloud computer, also for an image build or a refresh. All orgs share the starts of the app's Boat account.
  - **Org image:** the saved snapshot that every new cloud computer of an org starts from.
  - **Refresh:** an update of the org image that fetches the new commits of each chosen repository, in a cloud computer of its own.
- **Background:**
  - `docs/protocol/org-image.md` says that a push refreshes the org image at most once in 30 minutes, and that a daily timer refreshes it too.
  - The same doc says that each refresh is a start.
  - `readImageSchedule` in `worker/lifecycle/image-schedule.ts` sets the next daily refresh of every org. It does not check whether anyone used the org.
  - The $20 Boat plan gives all orgs together 12 starts a minute, 60 an hour, and 200 a day.
- **Problem:** Each org spends one start a day, also when nobody uses it. With 200 orgs, the daily refreshes alone use the starts of a whole day.
- **Impact if no action:** As orgs grow, idle orgs take the starts that members need to create and resume workspaces. Starts above the limit cost money, and then they fail.
- **Root question:** How does the org image stay fresh without spending starts on orgs that nobody uses?
- **Options:**
  - **A.** Skip the daily refresh when no workspace of the org was created or started in the last 7 days. A new workspace then fetches the newer commits itself. Effort: Small.
  - **B.** Drop the daily timer. Refresh after a push, at most once in 30 minutes, and before a create when the image is older than a day. A create then waits for the refresh. Effort: Medium.
  - **C.** Keep the daily timer for paid orgs only, once billing exists. The pricing change of 10 November 2026 offered this for free orgs. Effort: Small.
  - **D.** Change nothing. Effort: Small.
- **Left out:** None.
- **Wider fix:** A. It removes the idle case for every org, paid or free.
- **Previous examples:** Decision 25 D of 5 November 2026 turned off the automatic refresh for free accounts. Decision 45 removed that rule with billing on the same day.
- **Recommendation:** A. It saves the starts of idle orgs and keeps the image fresh for orgs in use.
- **Action:** ask the user, because A changes the refresh rule of `docs/protocol/org-image.md`.
