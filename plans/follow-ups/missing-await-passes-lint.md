# A missing await in a test passes the lint

- **Severity:** Medium. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-10, from branch `calummoore/account-routing-flake-fix`, as the blocked wider fix of the account routing replay flake.
- **Location:** `eslint.config.js`, the lint configuration of every package. `worker/test-support/native-runtime.ts`, the native fixture. `worker/lifecycle/account-routing.test.ts:72`, the fixed call.
- **Reason:** The recommended option adds lint rules, and the user decides each new lint.

- **Terms:**
  - **Floating promise:** a promise that the code does not await or handle. Its work runs beside the statements that follow it.
  - **`no-floating-promises`:** a rule of `typescript-eslint` that reports a floating promise in a statement. It needs type information from a TypeScript project.
  - **`no-misused-promises`:** a rule of `typescript-eslint` that reports a promise in a condition, or a promise that a callback returns where the caller expects no value. It needs type information too.
  - **Native fixture:** the test harness in `worker/test-support/` that runs the workspace Durable Object in a local Workers runtime, through Miniflare.
- **Background:**
  - The test "replays a lost allocation and resumes its disk through the stored secondary account" in `worker/lifecycle/account-routing.test.ts` called `start.restart()` without `await`. Pull request #137, commit `2f329f9d`, added the call.
  - The restart aborts the native object. A call of the test that ran during the abort got the text reply `Error: The native test fixture requested an object reset.` The fixture read that reply as JSON. So the test failed with `SyntaxError: Unexpected token 'E', "Error: The"... is not valid JSON`.
  - The test failed in four CI runs on 10 November 2026: 42809324418, 42815054593, 42824852311, and 42827704425. On a 4-core machine, 3 of 400 runs failed under load, and 1 of 60 runs failed on an idle machine. With `await`, 400 of 400 runs passed under the same load.
  - `eslint.config.js` is the only ESLint configuration. `npm run lint` checks every package with it, also the agent runner under `runner/` and the Mac app under `desktop/`. `npm run desktop:lint` runs the same file from `desktop/`.
  - The configuration uses the `typescript-eslint` recommended rules without type information. So the lint runs neither `no-floating-promises` nor `no-misused-promises`.
  - On 10 November 2026, one-time runs of the two rules with type information gave these results:
    - `no-floating-promises` reported the unfixed call at line 72.
    - After the fix, it reported 14 calls in `worker/` and `src/`, and each one is safe. 4 are `context.blockConcurrencyWhile(...)` calls in Durable Object constructors of test support files. 10 are `act(() => vi.advanceTimersByTime(...))` calls in 3 web app test files.
    - In all the TypeScript projects, it reported 16 calls: the 14, and 2 `notices.splice(...)` calls in mockup screens under `docs/mockups/src/screens/`.
    - `no-misused-promises` reported 9 more calls in all the projects: 4 web app props, 2 runner test servers, 2 Mac app callbacks, and 1 tool script. Each one needs a look.
  - Time and memory, on a 4-core machine with 8 GB:
    - `npm run lint` takes about 30 seconds. `npm run file-length:check` runs the whole lint again with one more rule, in about 32 seconds. So each second that the lint adds counts twice in the gate.
    - With type information for `worker/` and `src/`, one lint process peaks at about 1.75 GB of the 2.24 GB default heap. One process with all 9 TypeScript projects runs out of that heap.
  - The Mac app lint runs from `desktop/`. There, a configuration block for `src/**` also matches `desktop/src/`. So each block with type information needs its own `basePath`.
- **Problem:** No check finds a promise that the code does not await. Such a call races the calls that follow it, so a test fails only now and then.
- **Impact if no action:** A later missing await can add a new flaky test. Each one costs CI reruns and a search for the cause.
- **Root question:** How is a floating promise in any TypeScript package of the repository found or made harmless before the merge?
- **Options:**
  - **A.** Change nothing. A review can still find a missing await. A native call that gets a text reply now names the call, the status, and the text, so the next case is quicker to find. Effort: Small.
  - **B.** Turn on `no-floating-promises` with type information for `worker/`, through `tsconfig.worker-tests.json`. Mark the 4 constructor calls with `void`. The lint takes about 13 seconds more. Effort: Small.
  - **C.** B, and turn on the rule for `src/` too, through `tsconfig.app.json`. Give the 10 `act` calls a block body, or mark them with `void`. Do not allow `act` in the rule options, because an unawaited `act(async () => ...)` then passes too. The lint takes about 20 to 26 seconds more. Effort: Small.
  - **D.** Make the native fixture hold each host call to an object while a restart of that object runs. Then a restart without `await` cannot race. A call during a restart then waits, but on the platform it fails. It covers restarts only, not other missing awaits. Effort: Medium.
  - **E.** Make the native fixture reject each new host call to an object while a restart or a reset of that object runs. The error names the call and says to await the restart. A missing await before a restart then fails on every run, and the call still fails, as on the platform. It covers restarts and resets only. The guard must let the calls of the restart itself pass. Effort: Medium.
  - **F.** C, and the same rule for each other TypeScript project that the lint checks: the runner, the Mac app, the mockups, the tool and image scripts, and the root configuration files. Fix the 2 mockup calls. Run the lint for each package, because one process runs out of the default heap. The lint takes about 31 seconds more. Effort: Medium.
  - **G.** F, and also turn on `no-misused-promises`. It also finds a missing await in a callback or a condition, such as `setTimeout(() => start.restart())` or `step < 20 && start.job()`. Check and fix its 9 reports. The lint takes about 52 seconds more. Effort: Medium.
  - **H.** Make the native fixture record each promise that a fixture call returns. An `afterEach` hook then fails each test that did not await or handle one. It finds a floating fixture promise in any shape, on every run, and adds no lint time. It does not check product code or the other promises of a test. Effort: Medium.
- **Left out:** A retry or a longer time limit for the test, because each hides the defect. The whole `recommended-type-checked` preset of `typescript-eslint`, because G is better on every point for this goal. In `worker/`, `src/`, and `tools/`, the preset gave 800 reports, and G gave 18.
- **Wider fix:** G, a detection fix for the class. D, E, and H change the native fixture only.
- **Previous examples:** None found in the history of `main` or in `plans/follow-ups/`.
- **Related:** `plans/follow-ups/file-length-check-repeats-lint.md` has the same cost. The gate runs the lint twice, so each second that this item adds counts twice until that item is fixed.
- **Recommendation:** G. It also checks the runner, the Mac app, and the mockups, and it finds a missing await in a callback or a condition. It costs about 30 seconds more per lint run than C. The first recommendation was C.
- **Action:** ask the user, because the recommended option adds lint rules, and the user decides each new lint.
