# Open branches write a dropped org image field

- **Severity:** Medium. **Effort:** Small. **Confidence:** High. **Harder later:** Yes.
- **Kind:** Outside the scope.
- **Added:** 2026-11-09, from the options check of decision 217 on branch `calummoore/vercel-sandbox-provider`, as a problem outside its scope.
- **Location:** `worker/lifecycle/restored-image-alarm.test.ts:17` at commit `27cebd4c58f30241f7682eec1d95bb022b824c23` of branch `calummoore/conductor-alternative-architecture`, and `worker/lifecycle/restored-image-alarm.test.ts:16` at commit `23b5b88340eb0bed7608704cf60daf5ade556b0f` of branch `conductor/boat-native-remote-workspaces-milestone-15u`.
- **Reason:** The stale write lives on other open branches, and the change that found it edits no other branch.

- **Source:** Review. **Category:** Test.
- **Terms:**
  - **Org image fields:** six columns that `settings` held before `migrations/202611092305_org_images.sql`: `org_image_name`, `image_build_id`, `last_refresh_at`, `last_push_refresh_at`, `pending_push_refresh_at`, and `next_image_refresh_at`.
  - **`org_images`:** the D1 table with one org image record for each org and provider account, keyed by `(org_id, provider_account)`. It holds `image_name`, `image_build_id`, and the four refresh fields of the same names.
- **Background:**
  - `migrations/202611092305_org_images.sql` copies the six org image fields of each `settings` row to `org_images`. Then it drops them from `settings`, with no bridge for older code.
  - Outside `migrations/`, the repository code reads and writes these fields only through `org_images`.
  - `readOrgImage(db, orgId, providerAccount)` in `worker/lifecycle/org-image-data.ts` reads one record. `seedPublishedImage` in `worker/lifecycle/published-image-test-support.ts` seeds a published image, with the account `boat` by default.
  - A test sets a refresh deadline with `UPDATE org_images SET next_image_refresh_at = ? WHERE org_id = ? AND provider_account = ?`, as `worker/application-scheduled.test.ts` does.
  - Pull request #90, <https://github.com/Firna-AI/remote-code/pull/90>, is open from branch `calummoore/conductor-alternative-architecture` into `main`. Its head was `27cebd4c58f30241f7682eec1d95bb022b824c23` on 9 November 2026.
  - Pull request #106, <https://github.com/Firna-AI/remote-code/pull/106>, is open from branch `conductor/boat-native-remote-workspaces-milestone-15u` into `calummoore/conductor-alternative-architecture`. Its head was `23b5b88340eb0bed7608704cf60daf5ade556b0f`.
  - Pull request #96, <https://github.com/Firna-AI/remote-code/pull/96>, from branch `conductor/boat-native-remote-workspaces-milestone-15t`, merged into `calummoore/conductor-alternative-architecture` on 9 November 2026. Its head, `9b7815bd61ff27dae518e37f12f6b7153e1aeb82`, is part of the head of pull request #90. It is not open.
  - On these heads, `worker/lifecycle/restored-image-alarm.test.ts` sets a refresh deadline with `'UPDATE settings SET next_image_refresh_at = ? WHERE org_id = ?'`. It is line 17 at `27cebd4c` and at `9b7815bd`, and line 16 at `23b5b883`.
  - On 9 November 2026, a read of the lines that these branches add found no other use of the six fields.
- **Problem:** That test writes `settings.next_image_refresh_at`, which no longer exists after the move. When a branch with the test meets `org_images`, the D1 statement fails, and the test fails.
- **Impact if no action:** The `Complete gate` of the second merge fails, and that merge waits for a fix. This is a risk at the next merge, not a failure today.
- **Root question:** How do the tests of the open branches stay valid after the org image moves to `org_images`?
- **Options:**
  - **A.** When the branch of pull request #90 or #106 merges with the change that adds `org_images`, move each write and each read of the six fields there. Use `org_images` for the account `boat`, or `readOrgImage` and `seedPublishedImage`. For this test, use `UPDATE org_images SET next_image_refresh_at = ? WHERE org_id = ? AND provider_account = ?`, with `boat`. Run the complete gate on the combined branch before the merge into `main`. Effort: Small.
- **Left out:**
  - A change to those branches now, because their schema has no `org_images` until they merge the change that adds it.
  - A permanent search or lint for the six names, because a new gate needs the user's approval, and the existing gate already fails on the stale write.
  - A bridge in `settings` for older code, such as kept columns or a view, because the move drops the six fields with no bridge, as "When a deploy fails" in `docs/automatic-deploys.md` says.
- **Wider fix:** None. The `Complete gate` runs every test, so it catches each stale use at the merge.
- **Previous examples:** None found.
- **Related:** `plans/follow-ups/compatible-schema-rollout.md` designs migrations that keep older code working after the launch. Both items come from the same migration.
- **Recommendation:** A. It moves the write in the merge that first meets `org_images`, where the gate proves the fix.
- **Action:** fix after merge, apply A, because the stale write lives on other open branches, and this change must not edit them.
