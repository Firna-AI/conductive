# The share switch of agent logins stays

- **Severity:** Medium. **Effort:** Large. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-10, from item 6 of the work on branch `calummoore/openai-subscription-token-support` (pull request #177). On 11 November 2026 the user chose not to decide it now.
- **Location:** the share rules in `docs/protocol/isolation.md`, `src/shell/account/LoginShareSetting.tsx`, `worker/chat/login-access.ts`, and the column `agent_logins.no_reuse`.
- **Reason:** the user asked to remove the switch, and then chose on 11 November 2026 to leave the timing open.

- **Terms:**
  - **Share switch:** the account setting "Let other members use this login", stored as `no_reuse`. It lets other members' messages in the owner's sessions run on the owner's agent login. Decision 116 added it.
  - **Linked session:** the new session that the Worker starts for a member's message when the owner of the session does not share the login.
- **Background:**
  - On 10 November 2026 the user said that the switch is not real sharing, because it covers only a continuation of the same conversation by another member, and asked to remove it.
  - The removal takes out these parts:
    - the account switch and its "not saved" state
    - the share check of the Worker before each message
    - the linked session when a login is not shared
    - the `no_reuse` column and its typed default `defaultAgentLoginNoReuse`
    - the Terms sentence, the public guides, and the protocol rules
  - After the removal, every message in a session runs on the owner's login, as decision 105 did before decision 116.
  - The consumer terms of Anthropic and OpenAI forbid making an account available to others. Other members' continuations spend the owner's plan, so the protocol doc and the Terms page must state that risk again.
- **Problem:** The switch stays, although the user asked to remove it.
- **Impact if no action:** Members keep a setting that the user finds misleading, and the code keeps the linked session path.
- **Root question:** When, and in which change, does the share switch go away?
- **Options:**
  - **A.** Remove it in the next pull request after the ChatGPT sign-in merges. Cost: the switch stays until then. Effort: Large, about one day of agent work.
  - **B.** Remove it in its own branch from `main` at another time that the user chooses. Effort: Large.
  - **C.** Keep the switch, and change its words so that it says it covers continuations by other members. Effort: Small.
- **Left out:** Hiding the switch but keeping its code, because that leaves dead code.
- **Wider fix:** None.
- **Previous examples:** Decision 105 ran every message on the owner's login before decision 116.
- **Recommendation:** A. The removal then builds on the merged ChatGPT sign-in with no conflicts.
- **Action:** ask the user, because the removal deletes a feature on `main`, and the user chose to decide the timing later.
