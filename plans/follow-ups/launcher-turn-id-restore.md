# Launchers still restore the turn ID

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-11, from review round 1 of the branch `calummoore/github-push-failure`, finding 5.
- **Location:** `image/git-credential-helper.sh:3` and `:10`, the launcher in `installWorkspaceTools` of `worker/tools/image.ts:25`, the saved files of `worker/lifecycle/git-credential-helper.test.ts`, `worker/lifecycle/github-cli.test.ts`, and `worker/tools/image-context.test-support.ts:82`, and `image/github.md`, section "Git credential helper".
- **Reason:** the fix changes two image launchers outside the files of that branch, and it reaches a workspace only after Build computer and a new workspace.

- **Terms:**
  - **Turn ID:** `CONDUCTIVE_TURN_ID`, the ID of the running agent turn. The agent runner gives it to each agent process. The Worker uses it to choose whose GitHub token Git gets.
  - **Sandbox variables:** the env values that the Worker gives a cloud computer at each start. The sandbox provider writes them to `/run/ascii-secrets/env.sh`.
  - **Launcher:** a small shell script in the org image that loads the sandbox variables and then starts a program. The credential launcher is `/usr/local/bin/conductive-git-credential`. The tools launcher is `/usr/local/bin/conductive`.
- **Background:**
  - Until 11 November 2026, the sandbox variables held `CONDUCTIVE_TURN_ID=''`. A launcher that loaded them replaced the caller's turn ID with that empty value.
  - So both launchers save the caller's turn ID before they load the file, and restore it after. The tools launcher does the same for the machine origin and the workspace token.
  - Since the branch `calummoore/github-push-failure`, the Worker never puts a turn ID into the sandbox variables, also when an org env var has that name. `worker/lifecycle/runner-environment.test.ts` checks this. `docs/protocol/github-tokens.md` states it.
  - Three test fixtures still write a stale turn ID into the saved file, to show that the caller's value wins.
- **Problem:** The save and restore of the turn ID guards against a value that the sandbox variables no longer hold. Two places now keep one rule.
- **Impact if no action:** Readers of the launchers see a guard whose reason is gone. Nothing breaks.
- **Root question:** Which part stops the sandbox variables from replacing the turn ID of an agent command: the Worker only, or also each launcher?
- **Options:**
  - **A.** Remove the save and restore from the credential launcher. Move its two fixtures to saved files without a turn ID, and keep every assertion. Effort: Small.
  - **B.** Do A. Also remove `CONDUCTIVE_TURN_ID` from the restore list of the tools launcher. Keep its restore of the machine origin and the workspace token. Remove the empty turn ID from `worker/tools/image-context.test-support.ts`. Update `image/github.md`. Effort: Small.
  - **C.** Keep both guards as a stated rule: the caller's turn ID always wins over the sandbox variables. Give the reason in the launchers and in `image/github.md`: an org image can outlive the Worker version that writes its variables. Effort: Small.
  - **D.** Make the credential launcher read only `CONDUCTIVE_MACHINE_ORIGIN` and `WORKSPACE_TOKEN` from the file, in a subshell. Each other value of the caller then wins without a list of names. The helper then gets no other org variable from the file. Effort: Small.
- **Left out:** A helper that parses the variable file itself, and a separate file for the helper. D gives the same isolation with no parser and no second copy of the workspace token.
- **Wider fix:** D, because it keeps each value of the caller whatever its name. It does not protect a login shell, where only the Worker rule helps.
- **Previous examples:** Commit `b1d03858` added the restore to the tools launcher while the file held the empty turn ID.
- **Related:** `plans/follow-ups/org-node-options-reach-sandbox-software.md` changes the same credential launcher.
- **Recommendation:** B. It leaves one rule for the turn ID in both launchers at the same small cost.
- **Action:** fix after merge, apply B, because the change reaches two image launchers outside the branch and takes effect only with a new org image.
