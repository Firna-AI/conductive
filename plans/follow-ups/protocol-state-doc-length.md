# Secret requests and workspace life docs too long

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-20, from branch `calummoore/follow-up-a-waiting-request-hides-nj94`, in the docs work for the follow-up item "A waiting request hides Starting from the app". On 2026-11-26, branch `calummoore/needs-input-at-the-composer-milestones-3-j8a8` merged into it the item `plans/follow-ups/secret-requests-doc-length.md`, which proposed the same move of the secret requests doc. That item came on 2026-11-20 from branch `calummoore/workspace-capability-prompts-issue-2daj`, finding 3 of the Milestone 2 report of the capability prompts work.
- **Location:** `docs/protocol/secret-requests.md`, the sections "Temporary values" at line 197 and "Mixed requests" at line 238. `docs/protocol/workspace-life.md`, the section "Removed workspaces" at line 214. `docs/architecture/protocol-docs.md:57-62` and `docs/architecture/protocol-docs-workspaces.md:46-48`, the index entries of the two docs.
- **Reason:** Each branch that touched the two docs kept a narrow scope, and the split moves sections that those branches did not change.

- **Terms:**
  - **Protocol doc:** a doc under `docs/protocol/` that holds the requirements and the decisions in force for one area of the product.
  - **Protocol docs index:** `docs/architecture/protocol-docs.md` and its child pages, such as `docs/architecture/protocol-docs-workspaces.md`. They list each protocol doc and its linked pages.
  - **Stub section:** a short section that keeps the heading of a moved section and links to its new page, so that each old link to that heading still works.
  - **Temporary value:** a value that a member types into a secret request for a name that the org has no secret for. It lasts 15 minutes or until the workspace is archived.
  - **Removed workspace:** an archived workspace whose 14 days of Restore ended. It leaves the workspace list, and only a direct link opens its read-only chat.
- **Background:**
  - The `documentation` skill says: "Keep each doc short, about 250 lines. When you touch a doc that passes the target, split it into linked pages in the same change." The always-on rules split a file only after 300 lines.
  - `docs/protocol/secret-requests.md` holds the two secret calls of the workspace tools, the requests, covered requests, the time limit, temporary values, mixed requests, what the chat shows, the exact-copy filter, and the end of a request. Its linked pages `docs/protocol/secret-late-answers.md` and `docs/protocol/secret-variables.md` already hold the late requests, the late answers, and the variable names.
  - On `main`, `secret-requests.md` had 282 lines on 2026-11-19. The rule that Starting shows over needs input (#581, 2026-11-20) brought it to 291 lines. The change that tells each agent the capabilities of its session (#660, 2026-11-23) added three lines on when to use each secret call, to 294. The needs-input change of 2026-11-26 brought it to 299 lines, one line under the limit of 300.
  - `docs/protocol/workspace-life.md` had 286 lines before 2026-11-20. The Starting rule brought it to 288 lines, and later changes to 296.
  - None of these branches split a doc. Each kept its scope to its own rule.
  - Each doc already moved parts to linked pages, and it keeps a stub section for each part. `secret-requests.md` has stubs for "Late requests" and "Late answers", which link to `docs/protocol/secret-late-answers.md`. `workspace-life.md` has stubs for "Create a workspace", "Stop and resume", "Restart the software", and "Continue".
  - In `secret-requests.md`, "Temporary values" runs from line 197 to line 237, and "Mixed requests" from line 238 to line 248. Together they hold 52 lines on one topic: the values that a member types into a request. A mixed request names secrets of the org and names that the org has no secret for.
  - Two docs link to `secret-requests.md#temporary-values`: `docs/protocol/secrets.md:41` and `docs/protocol/secret-variables.md:42`. No file links to `secret-requests.md#mixed-requests`.
  - "What the chat shows", "The exact-copy filter", and "The end of a request" run from line 249 to line 299 of `secret-requests.md`. Eight links outside `plans/` reach the first two of these anchors.
  - In `workspace-life.md`, "Removed workspaces" runs from line 214 to line 286. Its 73 lines hold one topic: an archived workspace after the end of its Restore, with decisions 518 to 522.
  - 17 files outside `workspace-life.md` link to `workspace-life.md#removed-workspaces`: 11 in `docs/`, 4 in `src/`, 1 in `worker/`, and 1 in `tools/`. The doc itself links to it at lines 147 and 202.
  - "Removed workspaces" links to `#archive` of its own doc at lines 222 and 273. Its five other links name other pages in `docs/protocol/`, so they still work from a new page in the same folder.
- **Problem:** Both docs pass the length target by about 45 to 50 lines, and no branch that touched them split them.
- **Impact if no action:** Readers and reviewers read long docs to find one rule. Each later change that touches either doc meets the split rule again, and the next addition to `secret-requests.md` passes the limit of 300 lines.
- **Root question:** How do the two docs get back to about 250 lines without a change of any requirement?
- **Options:**
  - **A.** Move "Temporary values" and "Mixed requests" of `secret-requests.md` to a new page, such as `docs/protocol/secret-temporary-values.md`. Move "Removed workspaces" of `workspace-life.md` to a new page, such as `docs/protocol/removed-workspaces.md`. Give each new page the opening paragraph of a protocol doc, with a link to its parent doc. Keep a stub section with each old heading, so every old link still works. In the moved text, change the two `#archive` links to `workspace-life.md#archive`. Add each new page to the protocol docs index under its parent doc, and update the list of topics in the opening paragraph of `secret-requests.md`. `secret-requests.md` then has about 256 lines, and `workspace-life.md` about 228. Effort: Small.
  - **B.** Move other sections in the same way: "What the chat shows", "The exact-copy filter", and "The end of a request" of `secret-requests.md`, and "Start steps" with "Time limits of builds and starts" of `workspace-life.md`. Eight links reach the first two anchors of `secret-requests.md`, and seven files link to the two anchors of `workspace-life.md`, so more links need a stub section or an update. Effort: Small.
- **Left out:** Shortening the text in place, because each sentence holds a requirement or its reason, and the always-on rules forbid compacting text to meet a limit. Changing nothing, because it breaks the length rule. A move without stub sections, because each old link would then need a change in the same commit. Two items with one doc each, because the `plans` skill merges two items when one covers the problem of the other. A fixer can still move each doc in its own branch.
- **Wider fix:** None. The length rule of the `documentation` skill is already in force. A length check for Markdown would be a new gate, and only the user can add one.

- **Recommendation:** A. Each move takes one self-contained topic, and the stub sections keep every old link working with no other edit. Temporary values and mixed requests form one topic, the requests that ask a member for a value, and only two docs link to them.
- **Action:** fix after merge, apply A, because the split changes no requirement, and each branch that touched the docs kept a narrow scope.
