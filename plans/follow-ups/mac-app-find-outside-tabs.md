# The Mac app finds nothing outside a tab

- **Severity:** Low. **Likelihood:** Common. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-13, from the options check of the plan on branch `calummoore/oslo-xo4l`, which adds a find bar to the shown tab.
- **Location:** `desktop/src/menu.ts:25`
- **Reason:** The find bar of that branch covers only the shown tab of a workspace, and a find for the other pages of the Mac app needs its own approach.

- **Source:** Review.
- **Category:** Product bug.
- **Terms:**
  - **Shown tab:** the one tab that the centre column of a workspace draws: a session, a file, a Markdown preview, or a diff.
  - **Find bar:** the bar at the top of the shown tab that finds text in that tab, on ⌘F. The user chose it on 13 November 2026.
- **Background:**
  - The Mac app is an Electron app that shows the pages of the web app.
  - Its menu uses only the Edit, View, and Window roles of Electron. None of them has a Find item.
  - Electron gives `webContents.findInPage`, but no find bar.
  - In a browser, ⌘F opens the browser's own find on every page.
  - The find bar answers ⌘F only while a shown tab with text is on the page. On other pages, ⌘F goes on to the host.
- **Problem:** In the Mac app, ⌘F does nothing on a page without a shown tab with text, such as the workspace list, the Account page, or a settings page.
- **Impact if no action:** A Mac app user cannot find text on those pages. A browser user can.
- **Root question:** How does a Mac app user find text on a page that has no shown tab with text?
- **Options:**
  - **A.** Change nothing. Those pages are short lists, and the command palette finds workspaces and settings. Effort: Small.
  - **B.** Add Find to the Edit menu of the Mac app, with a small native find bar on `findInPage`, for the pages where the page does not offer Find. It needs a bridge from the page to the Mac app, which the protocol now rejects. Effort: Medium.
  - **C.** Use the find bar of the shown tab, with the whole page as its scope, on pages without a shown tab. It needs no bridge. It changes the rule that find covers only the shown tab. Effort: Medium.
- **Left out:** A find in the Mac app that also replaces the find bar of the shown tab. The user chose the find bar of the shown tab on 13 November 2026.
- **Wider fix:** None. This is a missing feature, not a defect class.
- **Previous examples:** Before the find bar, the Mac app had no find on any page.
- **Recommendation:** A. The pages without a shown tab are short, and the palette already finds their rows.
- **Action:** ask the user, because each option other than A adds behaviour that no requirement covers.
