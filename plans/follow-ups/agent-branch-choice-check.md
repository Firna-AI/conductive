# Check a branch before an agent starts from it

- **Severity:** Medium. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-11, from decision 280 of the plan for branch `calummoore/untitled-v3`, which adds the agent tools that match the Conductor CLI.
- **Location:** `worker/lifecycle/default-branch-command.ts:36`, `worker/lifecycle/workspace-start.ts`, and `worker/lifecycle/workspaces.ts`.
- **Reason:** No agent can choose a branch to start from yet. The plan that adds "Start from" to New workspace owns that choice, and its work is paused.

- **Source:** Design. **Category:** Docs or spec.
- **Terms:**
  - **Base branch:** the branch that the work of a workspace targets. A pull request run gets the branch of its pull request. Every other workspace gets the default branch of its repository, as `docs/protocol/base-branches.md` says.
  - **Start-from plan:** the plan `plans/start-from-github.md` on the branch `calummoore/new-chat-start-from-brainstorm`. It adds "Start from" for GitHub branches, pull requests, and issues to New workspace, and an agent tool that changes the target branch.
  - **Failed first start:** a create whose first start fails. The app keeps the workspace and its first message, and the workspace waits for Try again.
- **Background:**
  - The first start of a workspace fetches its base branch with `git fetch origin +refs/heads/<branch>:refs/remotes/origin/<branch>`, in `worker/lifecycle/default-branch-command.ts`.
  - Today the branch name comes from the default branch of the repository or from a GitHub event, so the name is always valid and exists.
  - On 11 November 2026, Cal chose to let the start-from plan give agents a branch choice, in place of a base branch option of `create_workspace`.
  - A failed first start gives the agent only `workspace_start_failed` and "The cloud computer could not start. Try again.", with no cause and no link to the kept workspace.
  - Only the owner of a workspace or an admin can archive it (decision 42).
- **Problem:** When an agent names a branch, a wrong name makes a workspace that fails at once and stays in the error state. Each retry makes one more failed workspace, and the agent does not learn why. A name such as `*` in the fetch refspec fetches every branch.
- **Impact if no action:** Failed workspaces pile up until an owner or an admin archives them, and an agent cannot tell a wrong name from another failure.
- **Root question:** How does a create with a branch that GitHub does not have tell the agent the cause, and leave no failed workspace behind?
- **Shared part of each option:** the Worker refuses a name that is not a valid Git branch name. A branch that equals the default branch counts as no branch, so an empty repository still works.
- **Options:**
  - **A.** No check before the create. The first start fails, the create reports it, and the failed workspace stays. Effort: Small.
  - **B.** The Worker asks GitHub for the branch before the create, with the GitHub token of the sender. An unknown branch gets a refusal with a named error, and no workspace starts. When GitHub cannot answer, the create goes on, and the start decides, as in A. Effort: Medium.
  - **C.** The Worker archives a workspace at once when its first start fails because the branch is missing. It changes the rule that a failed first start keeps its workspace. Effort: Medium.
  - **D.** A, and the tool help tells the agent to check the branch with `git ls-remote` first. An agent can skip the check. Effort: Small.
  - **E.** A, and a failed create names its cause, such as `base_branch_not_found`, and gives the link of the kept workspace. Effort: Medium.
- **Left out:** A fallback to the default branch, because the work would target a branch that the agent did not name. A push of the missing branch, because a typo would add a branch on GitHub. A create that waits until the branch exists, because a typo would hold the call until the start limit ends.
- **Wider fix:** B, built as one Worker check that a branch exists for a member. Each branch feature can use it.
- **Previous examples:** A pull request run takes its branch from the GitHub event, so it needs no check.
- **Related:** The start-from plan, `plans/start-from-github.md` on its branch, which owns the branch choice of agents.
- **Recommendation:** B. A refusal before the create leaves no failed workspace, and the agent learns the cause at once.
- **Action:** fix after merge, apply B, because Cal chose B on 11 November 2026, and the change that lets agents choose a branch must apply it.
