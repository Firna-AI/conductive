# Answer state check matches random identities by chance

- **Severity:** Medium. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-20, from the CI of PR #572 on branch `calummoore/follow-up-session-history-reads-scan-55fi`, an unrelated flaky test.
- **Location:** `worker/chat/runner-output-symbolic-held.test.ts:65-72`, the scenario "generated mask preserves source continuation", and `worker/chat/runner-output-symbolic-held.test.ts:106-110`, its check of the saved state.
- **Reason:** The assertion checks masking state outside the session history index fix, so one fix on `main` serves every open branch.

- **Source:** Implementation.
- **Category:** Test.
- **Terms:**
  - **Held end:** the end of an unfinished agent answer that the Durable Object holds back, because it can still become a copy of an active value.
  - **Symbolic answer state:** the saved state of the answer filter that lists no value. Each held entry keeps a random salt and opaque identities in place of values.
  - **Identity:** the HMAC-SHA-256 of a value under the app key, with the workspace and the salt in its input, written as 43 base64url characters.
  - **base64url:** a text form of bytes that uses only `A` to `Z`, `a` to `z`, `0` to `9`, `-`, and `_`.
  - **Complete gate:** `npm run check`. CI runs it as the job `Static checks` and four `Tests` shards. The job `Complete gate` passes only when each of them passes.
- **Background:**
  - The test "masks held whole copies after value changes and keeps exact longer and fallback matches" runs seven scenarios. The control `CONDUCTIVE_SYMBOLIC_ANSWER_STATE` is on, so the filter saves the symbolic answer state. Each scenario sets the active values `before` and sends the text `first`. Line 90 then saves `JSON.stringify(await answerState(f))` as `held`.
  - Lines 106-110 check that `held` holds no value of `before` as a substring. The message is "saved state contains no whole value".
  - The scenario "generated mask preserves source continuation" sets the active values `abc` and `bcdef`, and sends the text `abc`. Then it sets only `bcdef`, sends `def!`, and expects the shown text `[redacted][redacted]!`. Commit `884f6142` (#519) added it on 19 November 2026.
  - `answerState` in `worker/chat/runner-output-symbolic.test-support.ts:19` returns the decrypted entries that `parseHeld` in `worker/chat/output-filter-records.ts` reads.
  - A symbolic entry holds the held `event` with its text, `secrets: []`, and `symbolic`. `symbolic` holds the `salt`, `contexts` of `{ identity, matched }`, and `matches` with runs and entries of `{ offset, identity }`. The entry of a literal `[redacted]` has the identity `marker`.
  - `prepareOutputState` in `worker/chat/output-filter-state.ts:70` makes the salt with `randomToken()`: 32 random bytes as 43 base64url characters. `outputCandidates` in `worker/chat/output-filter-identity.ts` makes each identity with that salt. So the salt and each identity are new random text in each run.
  - The check protects two requirements of [The saved state of the filter](../../docs/protocol/answer-text-secrets.md#the-saved-state-of-the-filter). The state lists no value. A held end in that state holds no whole copy of an active value.
  - On 20 November 2026, CI run 44741220791, job 136305072058, failed this test in shard 2 of the `Tests` jobs, on commit `7ecc06fe`. Shard 2 passed 1,133 tests and failed 1. `Static checks`, the `Rust gate`, and the other three shards passed. The job `Complete gate` failed, because shard 2 failed.
  - The failure text was `AssertionError: generated mask preserves source continuation: saved state contains no whole value: expected '[[],[{"event":{"sessionId":"chat-0001…' not to contain 'abc'`.
  - In that saved state, the held event text was empty, and `secrets` was `[]`. The context identity was `My95VS_8wzaabchBJ22n77QtytE32dMSdF_LaDwTPic`, which holds `abc` at index 11 by chance. The salt did not hold `abc`. So the state held no value, and the run showed no leak.
  - The branch changed none of the files above. They matched `main` at `458bd46d`. No separate rerun of the failed job ran. The unchanged test passed in the local complete gate of the branch, with all 4,689 root tests. A documentation commit to the branch started fresh CI instead of a rerun.
  - A local run can show the failure on demand. Give `prepareOutputState` a fixed salt for which an identity of `abc` or `bcdef` holds `abc`, then restore the code.
  - The fixture runs the production workspace object in the local Workers runtime, as `worker/chat/README.md` says under "Tests". The salt comes from `randomToken()` inside that object.
- **Problem:** The check scans the whole saved state as text, also the random salt and identities. A random token can hold the short test value `abc`. The test then fails, though the state holds no value.
- **Impact if no action:** The required gate can fail with no code change. Each failure costs a new CI run and reduces trust in this secret check.
- **Root question:** How does the check that the saved answer state holds no value give the same result on every run, and still check every saved field?
- **Options:**
  - **A.** Keep every assertion. Give the scenario values with a character that base64url never uses, with the same lengths and overlap. Set the values `a:b` and `:bcde`, and send the text `a:b`. Then set only `:bcde`, and send `cde!`. The end `:b` of the first value is the start of the second value, as `bc` is now. Keep the expected text `[redacted][redacted]!`. A random salt or identity can then never hold a value of this scenario. Cost: it fixes this scenario only. A later short value of base64url characters can fail in the same way. Effort: Small.
  - **B.** Add one helper to `worker/chat/runner-output-symbolic.test-support.ts` for the check of a saved answer state. It checks `symbolic.salt` and each `identity` by their form: 43 base64url characters, or `marker` for a match entry. It scans each other field for each whole value, as now. Use it in each test that scans a saved answer state. Cost: the salt and the identities lose the substring check. This loosens an assertion, which needs the user's approval. Effort: Small.
  - **C.** Give the workspace object a fixed random source in this test, so that the salt and the identities are the same in each run. Keep every assertion. Cost: the test process cannot replace the random source of the object, so this needs a seam in product code. A later change of the test key, the identity input, or the seed can put a value in a token again. The test then fails in each run until someone picks another seed. Effort: Medium.
- **Left out:**
  - A retry, a repeat, a skip, a quarantine, or a longer time limit. Each hides the flake, and the testing rules forbid them for a flaky test.
  - Longer values of base64url characters only. They make a match rare but still possible, and they change the lengths of the scenario. A is better on every point.
  - A check of the held event text alone, or of each value only as a whole JSON string. Each misses a value in another field, or inside a longer text.
  - A removal of `abc` from the check, or of the scenario. Each drops a check of a requirement.
  - A lint or a guard that refuses short test values. It adds a new check, which the always-on rules reserve for the user. A removes the only such value in these checks.
- **Wider fix:** B. It takes the random tokens out of the substring scan of each saved-state check. It loosens the check of those fields, so it waits for the user's approval. The branch that applies A records B as its own item, with the kind Needs decision.
- **Previous examples:** None found of a test value that matches a random token. `plans/follow-ups/short-key-redaction.md` records the same chance match in product code: the gateway finds a short own endpoint key by chance in ordinary answer text.
- **Recommendation:** A. It keeps every assertion, and it makes a random match impossible for the one value at risk, with no user approval. B best protects the codebase from the class, but it loosens an assertion.
- **Action:** fix after merge, apply A, because the failed masking-state check is outside the session history index fix.
